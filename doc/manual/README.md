# BTstack Manual

This directory builds the BTstack Manual as HTML and PDF. The authored
Markdown lives in `docs-template/`; the build scripts add generated API,
example, port, and GATT documentation.

## Prerequisites

Install the Python dependencies listed in `requirements.txt`. Building the PDF
also requires Pandoc, WeasyPrint, pdfLaTeX, and qpdf.

## Build

```sh
make html   # HTML site in btstack/
make pdf    # PDF in btstack.pdf
make        # both
```

`make docs` first creates `docs-markdown/` from the templates and generated
content, then produces the processed `docs/` input used by both output formats.
The HTML build uses MkDocs and post-processes code blocks. The PDF build
collects the Markdown into `latex/btstack_generated.md`, renders it with
Pandoc and WeasyPrint, creates the cover page with pdfLaTeX, and combines both
PDFs with qpdf.

Use `make clean` to remove generated documentation and build outputs before a
full rebuild.

## API reference

`markdown_create_apis.py` discovers headers under `src/` with an `@title`
comment or an `API_START` marker and renders the declarations between
`API_START` and `API_END`. Headers without a title use their filename.
The generated `btstack_event.h` getter header is included explicitly. API pages
are grouped by area in the HTML sidebar and PDF appendix, and sorted by title
within each group. The group assignments live in `markdown_create_apis.py`;
new unclassified root headers appear under Other APIs. Comment out a group in
`API_GROUPS` to omit its pages from HTML and PDF, then rebuild the manual.
The header title and overview introduce each API page; documented functions are
rendered with their signatures, descriptions, parameters, return values, and
source links. Other declarations, including types, macros, and preprocessor
conditions, remain as C excerpts in their original order.

Function documentation comes from the comment immediately preceding the
declaration. Use `@brief`, `@param name`, `@return`, and `@note` as appropriate.
In header comments, write HTTPS links as `https:&#47;&#47;example.com/...`
so the comment contains no double slash; Markdown renderers decode the entities.
The renderer understands the C declaration patterns used in BTstack headers;
when adding a new declaration form, check the generated page and extend the
renderer if needed. Event getter declarations and comments are generated by
`tool/btstack_event_generator.py` from the event annotations in `src/bluetooth.h`
and `src/btstack_defines.h`. Update those annotations or the generator rather
than editing `src/btstack_event.h` directly.

HTML has one page per header. The PDF includes all API pages in one appendix,
excluding the generated event getter reference. The HTML event getter page
groups accessors by event macro in its navigation. The older
`pdf_old` target generates the manual body via LaTeX; `pdf` uses WeasyPrint.

Run the renderer checks with `python3 -m unittest discover -s tests`.
