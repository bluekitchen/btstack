# Consolidated OS-branched dialer engine merge

This merge folds a working-macOS source tree and a Windows-focused in-tree port into one OS-branched codebase under `port/dialer/`. The app layer now has a single recording path (the VAD `call_recorder`, fed by `sco_audio.c`, surfaced to the host through `ipc.c` adapters), a single audio-engine lifecycle owner (`main.c`'s edge-detected `on_hfp_status_changed`), and OS-specific code moved behind `_WIN32` / `__APPLE__` / Linux guards. The IPC command dispatch was made portable (`strcmp`, not `_stricmp`) and firmware-path/exe-dir resolution branches per OS with a `MAX_PATH` fallback on POSIX. The four design decisions under review are implemented as described; the issues below are behavioral edge cases in the merged code, not structural regressions.

Watch for: an over-broad SCO disconnect match that can stop recording on an unrelated link teardown (confirmed); the stereo-mix path silently drops samples when a single SCO delivery exceeds the 2048-sample queue (confirmed, cosmetic vs. the continuous WAV/FLAC).

**Verdict**: NEEDS_CHANGES

## High-level view

Recording is genuinely single-path. `sco_audio.c` pushes decoded RX into `call_recorder_write_rx` and mic TX into `call_recorder_write_tx`, starts the recorder on SCO up and stops it on SCO down; `main.c` wires the recorder's lifecycle callbacks to the `ipc_on_recording_*` adapters that emit `call-started` / `segment-ready` / `call-ended`. No trace of the removed `ipc_recording_*` WAV writer remains anywhere in `src/`.

The audio-engine lifecycle has exactly one owner. `audio_render_start/stop` and `audio_capture_start/stop` are called only from `main.c` (and the out-of-scope `test_main.c`), gated by the `s_audio_engines_running` edge flag. `sco_audio.c` sets sample rates on SCO connect but never starts or stops the engines, and `on_sco_rx_pcm` in `main.c` is a deliberate no-op because `sco_audio.c` already fans decoded RX out to render and recorder.

Cross-platform guarding is consistent. `bt_controller.c` branches exe-dir resolution across `_NSGetExecutablePath` / `/proc/self/exe` / `GetModuleFileNameA` and defines `MAX_PATH` from `PATH_MAX` on POSIX. `ipc.c` dispatch uses `strcmp`. The `status` force-emit resets the dedupe cache to a sentinel (`-1`) that no real call state can equal, so the forced re-emit is never suppressed.

The remaining concerns are localized: the SCO disconnect handler matches too broadly, and the stereo interleave buffer caps per-call copies at 2048 samples without carrying the remainder.

<summary>Issues (2)</summary>

1. **Over-broad SCO disconnect match** — `sco_audio.c` `HCI_EVENT_DISCONNECTION_COMPLETE` fires on `handle == s_stats.sco_handle || s_stats.is_connected`; the `|| is_connected` clause stops recording and clears SCO state when *any* connection (e.g. the ACL link) disconnects while SCO is up. Match on the SCO handle only.
2. **Stereo-mix sample drop above 2048** — `call_recorder_write_rx/tx` clamp the per-call copy into the stereo queues to `STEREO_CHUNK_MAX` (2048) and discard the remainder; the merged stereo file loses samples on any single SCO delivery larger than that, while the continuous WAV/FLAC keep them. Loop/flush the full input instead of clamping.

### SCO disconnect handler matches too broadly

```c
case HCI_EVENT_DISCONNECTION_COMPLETE: {
    hci_con_handle_t handle = hci_event_disconnection_complete_get_connection_handle(packet);
    if (handle == s_stats.sco_handle || s_stats.is_connected) {
        ...
        s_stats.is_connected = false;
        s_stats.sco_handle = HCI_CON_HANDLE_INVALID;
        call_recorder_stop();
    }
```

The `|| s_stats.is_connected` clause makes this fire for a disconnection on *any* handle while a SCO link is active — including the ACL/SLC link or an unrelated connection. When that happens the handler marks SCO down and calls `call_recorder_stop()` even though the SCO handle is still live, cutting the recording short and desyncing `s_stats` from the actual SCO state (confirmed, `sco_audio.c` DISCONNECTION_COMPLETE handler). Match on `handle == s_stats.sco_handle` alone; the `is_connected` disjunct should be dropped.

### Stereo interleave drops samples above the queue cap

`call_recorder_write_rx` / `call_recorder_write_tx` append incoming samples to fixed 2048-entry queues:

```c
uint32_t space = (s_recorder.rx_q_count < STEREO_CHUNK_MAX) ? (STEREO_CHUNK_MAX - s_recorder.rx_q_count) : 0;
uint32_t to_copy = (num_samples < (int)space) ? (uint32_t)num_samples : space;
```

Anything beyond `space` is dropped for the stereo mix, and `flush_stereo_buffer()` only drains `min(rx_q_count, tx_q_count)` per call. The continuous `wav_rx`/`wav_tx` and their FLAC counterparts receive the full `num_samples` earlier in the same function, so per-channel files are complete; only the merged `full_duplex_stereo` file loses the overflow. SCO frame deliveries are far smaller than 2048 samples in normal operation, so this is unlikely to bite in practice, but it is a silent data-loss path with no logging (confirmed). Carrying the remainder (flush, then copy the rest) removes the asymmetry.

### Notes on the verified design decisions

Initialization order looks inverted but is safe: `main.c` sets the recorder callbacks and recordings-root dir at step 2, before `sco_audio_init()` calls `call_recorder_init()` at step 5. `call_recorder_init()` only `memset`s the `s_recorder` struct; the callback pointers and `s_recordings_root_dir` are separate file-scope statics init does not touch, so the earlier configuration survives (confirmed).

Both `on_hfp_status_changed` (on the audio edge) and `sco_audio.c`'s SYNCHRONOUS_CONNECTION_COMPLETE handler set the render/capture sample rates to identical values (16 kHz mSBC, 8 kHz CVSD) — a harmless double-set, not a second lifecycle owner.

The `status` force-emit is correct: `ipc_handle_stdin_line` resets `s_last_call_state = -1` before `ipc_emit_state`. Since `dialer_call_state_t` starts at `HFP_STATE_IDLE == 0`, no real state equals `-1`, so `(int)status->call_state != s_last_call_state` is always true and the forced emit is never suppressed by the dedupe (confirmed, `ipc.c` `emit_state` + `status` branch).
